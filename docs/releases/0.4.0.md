# APIVault v0.4.0 acceptance record

**Release classification:** 0.x prerelease. This is not a production or general-availability launch.

## Scope accepted

- Contributor submission, private submission tracking, opt-in public profiles, and privacy projections.
- Moderation prioritization, reviewer decisions, audit history, and approval returning records to evidence-based verification rather than publishing them automatically.
- Bounded, dry-run-first, resumable and idempotent manifest imports with durable checkpoints, provenance, duplicate/conflict diagnostics, and PostgreSQL recovery/concurrency coverage.
- Operator-facing moderation, catalogue freshness, and importer health metrics, with definitions in [PROJECT_METRICS.md](../PROJECT_METRICS.md).
- Direct non-admin Server Action mutation rejection, protected admin workflows, and CI-only auth rate-limit test override.

## Source and licensing boundary

- No third-party source-specific ingestion adapter or automatic provider-directory scraper is included in this release.
- The Go importer consumes operator-supplied manifests. The curated starter manifests are manually maintained discovery/review candidates, not an assertion that any provider endorses APIVault.
- Their dataset-level license is `NOASSERTION`; this is not a grant of rights to redistribute provider data. Provider terms and attribution must be reviewed before any future source adapter or bulk dataset is used.
- Imported candidates remain pending/unverified. The importer cannot verify, feature, or publish records.

## Recovery and operations

The importer failure/retry procedure is documented in [OPERATIONS_RUNBOOK.md](../OPERATIONS_RUNBOOK.md), and the PostgreSQL backup/restore procedure is documented there as well. The existence of backup scripts is not evidence of a successful restore.

Hosted validation, an isolated restore drill, centralized logs/metrics, and external alert delivery are not claimed as complete by v0.4.0. They remain explicit operational readiness gates for the 0.5.0 beta milestone. The hosted beta currently deploys from `dev`; a live deployment status alone is not a recorded smoke-test or alert-delivery result.

## Release validation

The release PR must pass Application CI (unit and PostgreSQL integration tests, lint, typecheck, production build), Browser E2E, Go importer/verifier CI, repository hygiene/security checks, and Docker build/smoke tests on the exact release snapshot commit. Record the resulting run links in the release PR before promotion to `stable`.

## Catalogue scope

The 1,000 verified-API threshold belongs to v0.5.0, not v0.4.0. No catalogue scale claim is made by this release. Pending, unverified, duplicate, archived, endpoint-only, version-only, and mirror records do not count toward that future gate.
